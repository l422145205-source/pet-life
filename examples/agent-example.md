# PetLife 示例：把“主子的生活”交给 Agent 整理

以下使用完全合成的资料，展示如何调用 Skill；不是真实用户聊天、真实宠物记录或独立模型评测。

## 对 Agent 说

> 用 $pet-life 读这些粮袋标签、小票和我的照顾说明。两只猫一起吃同一袋粮，小票有一张重复了。算算还够吃多久、10月记了多少开销，顺便给我一份出门3天的托管交接单。以2026年10月3日为截止日，最后那张模糊小票别猜。

输入：[原始资料文字包](../assets/source-packet.example.md)；用于计算的结构化结果：[household.example.json](../assets/household.example.json)。实际使用时可提供照片、文字或已有记录；照片读取依赖宿主 Agent 的能力。

## Agent 应完成的工作

1. 从标签提取“每袋2kg”“3800 kcal/kg”“每罐85g、80kcal”，不把一袋和一次订单混淆。
2. 把两只猫的现有日用量分开保存，汇总同一袋粮的消耗。识别重复小票、模糊小票和未来记录。
3. 调用 Skill 自带脚本核算，而不是在回答里口算一串数字。
4. 用源资料说明结果，交付生活账本和托管单；联系人未提供时，交接单保持草稿。

## 该资料包的核算结果

> **年糕和包子的“人类开销审计”：本期已记209元。**
>
> 干粮账面剩2310g，两只合计每天90g，约够25.7天；罐头账面剩7罐，每天合计1罐，约够7天。最近一次实物盘点在10月1日晚，之后只扣了明确记录的消耗，实际库存仍需以实物为准。
>
> 按最近小票和主人既定日用量估算，两只每天合计13.22元。这是日用量成本预测，与本期实际购买支出不同。
>
> 3天托管：年糕准备150g干粮和1.5罐湿粮；包子准备120g干粮和1.5罐湿粮。合计270g干粮、3罐湿粮。喂食位置和防抢食要求分开列出。紧急联系人尚未提供，交接单仍是草稿。

这里的日用量来自合成主人说明，不是为现实宠物制定的新喂养方案。

## 可以亲自复现

```sh
python scripts/petlife.py build --input assets/household.example.json --as-of 2026-10-03 --trip-days 3 --out work/pet-life-demo
```

实际脚本产物：[生活账本](brief.md) · [托管交接单](care-card.md) · [计算记录](report.json)。脚本不读取照片，也不声称完成了 OCR；它接收 Agent 核对后的结构化事实。

## 其他好用的说法

- “这几张小票有优惠券，别按原价算，帮我整理本月猫咪工资条，语气可以像猫老板审计。”
- “这袋粮涨价了，我给你新旧两张小票，按每100g的实际价格比，不要只看整袋价格。”
- “我要交给朋友照顾，输出一份手机上能直接看的交接单；缺什么放最上面。”
- “今天又买了一样东西，更新本地账本，再发同一张小票不能重复入账。”
